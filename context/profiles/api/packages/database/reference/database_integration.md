# Database Integration

Database integration workflow covering async engine setup, session management, repository creation, Alembic migrations, and connection pooling.

Procedure for integrating SQLAlchemy 2.0 async with a FastAPI application. The workflow establishes an async engine, configures session-per-request through dependency injection, creates the repository layer, and sets up Alembic for schema migrations. The result is a database layer where each request operates within an isolated transaction.

## Prerequisites

Gather before starting:

- **Database URL**: PostgreSQL connection string with the `+asyncpg` driver (e.g., `postgresql+asyncpg://user:pass@host/db`).
- **Schema design**: Tables, columns, relationships, and constraints defined at minimum in outline form.
- **Project setup complete**: uv environment initialized, pyproject.toml configured.

Install required dependencies:

```bash
uv add sqlalchemy asyncpg alembic
uv add --dev aiosqlite   # For test database (SQLite async)
```

## Integration Workflow

### 1. Configure the Async Engine

Create the engine and session factory in a dedicated database module. Initialize the engine once during application startup through the lifespan context manager.

```python
# app/database.py
from sqlalchemy.ext.asyncio import async_sessionmaker, create_async_engine

engine = create_async_engine(
    settings.database_url,
    pool_size=20, max_overflow=10,
    pool_pre_ping=True, pool_recycle=3600,
)
async_session_factory = async_sessionmaker(engine, expire_on_commit=False)
```

Set `expire_on_commit=False` to prevent `MissingGreenlet` errors when accessing attributes on committed objects in async contexts.

[Database Patterns](sqlalchemy_async.md)

### 2. Create the Session Dependency

Provide database sessions through a FastAPI dependency. The session commits on success and rolls back on failure, establishing a transaction-per-request boundary.

```python
async def get_session() -> AsyncGenerator[AsyncSession, None]:
    async with async_session_factory() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
```

Register engine disposal in the application lifespan context manager. Call `await engine.dispose()` after `yield` in the lifespan to clean up connections on shutdown.

[FastAPI Patterns](../../fastapi/reference/fastapi.md)

### 3. Define ORM Models

Use SQLAlchemy 2.0 declarative style with `Mapped` and `mapped_column`. Create a shared `Base` class in `app/models/base.py` and define one model file per domain entity.

```python
# app/models/base.py
from sqlalchemy.orm import DeclarativeBase

class Base(DeclarativeBase):
    pass

# app/models/user.py
class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    name: Mapped[str] = mapped_column(String(100))
```

### 4. Create Repository Classes

Repositories encapsulate database queries behind typed interfaces. Each repository handles one aggregate root.

```python
# app/repositories/users.py
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

class UserRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def get(self, user_id: int) -> User | None:
        result = await self._session.execute(
            select(User).where(User.id == user_id)
        )
        return result.scalar_one_or_none()

    async def create(self, user: User) -> User:
        self._session.add(user)
        await self._session.flush()
        return user
```

Use `flush()` instead of `commit()` in repositories. The session dependency handles commit and rollback at the request boundary.

### 5. Set Up Alembic Migrations

Initialize Alembic and configure it for async operation:

```bash
uv run alembic init alembic
```

Update `alembic/env.py` to use the async migration runner. Set `target_metadata = Base.metadata` and wrap `context.run_migrations()` inside `engine.connect()` with `run_sync`. Generate and apply the initial migration:

```bash
uv run alembic revision --autogenerate -m "initial schema"
uv run alembic upgrade head
```

Review every autogenerated migration before applying. Autogenerate misses index renames, data migrations, and constraint modifications.

### 6. Verify the Integration

Confirm database connectivity by running the application and hitting a health check endpoint:

```bash
uv run uvicorn app.main:app --reload
uv run basedpyright
uv run pytest tests/ -v
```

## Decision Support

### Pool Configuration

| Parameter | Development | Production | Rationale |
|-----------|------------|------------|-----------|
| `pool_size` | 5 | 10-50 | Match expected concurrent requests |
| `max_overflow` | 0 | 5-20 | Allow burst capacity |
| `pool_pre_ping` | False | True | Detect dead connections |
| `pool_recycle` | None | 3600 | Prevent stale connections |
| `echo` | True | False | SQL logging for debugging |

### Loading Strategy

| Relationship | Strategy | When |
|-------------|----------|------|
| Many-to-one | `joinedload` | Always needed with parent |
| One-to-many | `selectinload` | Loading collections |
| Many-to-many | `selectinload` | Loading collections |
| Optional | `selectinload` or skip | Load only when requested |

## Troubleshooting

**MissingGreenlet error**: Accessing a lazy-loaded relationship in async context. Use explicit eager loading (`selectinload`, `joinedload`) in queries, or set `expire_on_commit=False` on the session factory.

**Connection pool exhausted**: Increase `pool_size` and `max_overflow`. Verify that all sessions close properly through the dependency teardown. Check for long-running transactions holding connections.

**Alembic cannot detect model changes**: Verify that all model modules are imported before `target_metadata` is set in `env.py`. Use an explicit `import app.models` statement.
